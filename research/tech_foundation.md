## 1. Phaser 4 vs Phaser 3: status, what changed, and the recommendation

### Takeaway
Phaser 4.2.1 (released 9 July 2026) is the current stable line on npm. Phaser 3 ended at 3.90.0 (23 May 2025) with no maintenance branch, so the recommendation is Phaser 4.2.1, pinned exactly, with Phaser 3.90.0 kept only as a fallback if a needed plugin fails.

### Cited Findings

- jsDelivr's package index lists dist-tag `latest` = 4.2.1 and versions 4.0.0-alpha.0 through alpha.4, beta.1 through beta.8, rc.1 through rc.7, then 4.0.0, 4.1.0, 4.2.0, 4.2.1. The newest Phaser 3 versions listed are 3.90.0, then 3.88.2, 3.88.1 (no 3.89.x exists). Source: [jsDelivr data API](https://data.jsdelivr.com/v1/packages/npm/phaser)
- Release dates from the changelogs: 4.0.0 "Caladan" 10 April 2026; 4.1.0 "Salusa" 30 April 2026; 4.2.0 "Giedi" 19 June 2026; 4.2.1 "Giedi" 9 July 2026. Source: [Phaser repo changelog/v4](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/CHANGELOG-v4.0.0.md); [GitHub releases](https://github.com/phaserjs/phaser/releases); phaser.io states 4.2.1 "was released on 9th July 2026" Source: [phaser.io/download/stable](https://phaser.io/download/stable)
- Release-candidate history (GitHub shows day and month only; the years are inferred from list order): rc.3 16 May, rc.4 23 May (same day as 3.90.0, 2025), rc.5 22 Aug, rc.6 23 Dec, rc.7 25 March (2026). Source: [GitHub releases](https://github.com/phaserjs/phaser/releases)
- Press coverage dated 14 April 2026 called Phaser 4 a "completely revamped WebGL-based renderer" release. Source: [gamedev.net mirror of GameFromScratch](https://gamedev.net/news/2759-phaser-4-released/)
- Cadence after 4.0.0: three releases in about 13 weeks (10 April to 9 July 2026), then none for about 16 weeks (as of 1 Nov 2026). The default branch's last commit is 21 Aug 2026 ("Create CHANGELOG-v4.3.md"); that stub lists one entry, `TintModes.MULTIPLY_ADD`. Version 4.3 is not on npm. Source: [Phaser repo](https://github.com/phaserjs/phaser) (clone, `changelog/v4/4.3/CHANGELOG-v4.3.0.md`); [npm registry](https://registry.npmjs.org/phaser/latest)
- What 4.2.1 fixed (a good sample of the bug types in the line): stencil invert, framebuffer stencil clearing, ESM-build namespace access, ScaleManager not resizing to its parent container, tweens with `startDelay` stuck in their start state. Source: [CHANGELOG-v4.2.1](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.2.1/CHANGELOG-v4.2.1.md)
- Phaser 3: the last release is 3.90.0 "Tsugumi", 23 May 2025. The repo's CHANGELOG index lists no later 3.x. Source: [Phaser CHANGELOG.md](https://github.com/phaserjs/phaser/blob/master/CHANGELOG.md); [GitHub releases](https://github.com/phaserjs/phaser/releases)
- `git ls-remote --heads` on the Phaser repo returns only `master`, `arcade-physics-2`, `audio-revamp`, `ben-project-mask`, `webgl-wrappers`. There is no v3 branch. Tags include `v3.90.0` and every `v4.*` tag. Source: [Phaser repo](https://github.com/phaserjs/phaser) (command output, 2026-11-01)
- The repo README is now Phaser 4 centered and says it ships AI-agent skills: "Point your AI coding agent at the `skills/` folder". It also ships a dedicated v3-to-v4 migration skill. Source: [Phaser README](https://github.com/phaserjs/phaser) (lines 143 and 196 in the clone)
- The published npm package includes the `skills/` folder: 36 SKILL.md files (scenes, physics-arcade, tilemaps, filters-and-postfx, loading-assets, scale-and-responsive, v3-to-v4-migration, v4-new-features, and more). Source: [jsDelivr file listing for phaser@4.2.1](https://data.jsdelivr.com/v1/packages/npm/phaser@4.2.1?structure=flat)
- Renderer: the v3 Pipeline system is replaced by RenderNodes. Custom WebGL pipelines must be rewritten. Do not make direct `gl` calls. The Canvas renderer still exists but is deprecated, and most v4 features are WebGL only. Source: [Migration Guide sections 1 and 2](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/MIGRATION-GUIDE.md)
- FX and Masks are unified as Filters. Each game object or camera has `filters.internal` and `filters.external` lists. Filters work on any game object or camera. `BitmapMask` is gone (use the `Mask` filter). Bloom, Shine and Circle FX became Actions; Gradient FX became a Gradient game object; `ColorMatrix` methods moved under `.colorMatrix`. Source: [Migration Guide section 3](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/MIGRATION-GUIDE.md)
- Filter factory methods present in the Phaser 4 source include `addBlocky`, `addPixelate`, `addQuantize`, `addGradientMap`, `addMask`, `addColorMatrix`, `addGlow`, `addBlur`, `addBokeh`, `addBarrel`, `addDisplacement`, `addKey`; the skill file also shows `addVignette`. Source: [Phaser repo `src/gameobjects/components/FilterList.js`](https://github.com/phaserjs/phaser) (clone); [filters skill](https://github.com/phaserjs/phaser/blob/master/skills/filters-and-postfx/SKILL.md)
- Lighting: `sprite.setLighting(true)` replaces `setPipeline('Light2D')`. Lights have an explicit `z`. Objects can self-shadow. Lighting changes the shader and breaks render batches. Source: [Migration Guide section 10](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/MIGRATION-GUIDE.md)
- Cone lights arrived in 4.2.0: `lights.addConeLight(x, y, radius, rgb, intensity, rotation, innerAngle, outerAngle, z)`. The docs name flashlights, vision cones and searchlights as uses. They need WebGL, `this.lights.enable()`, and `setLighting(true)` on lit objects. Advice from the docs: keep the number of cone lights low, and prefer one player cone plus a few local lights. Source: [Phaser 4 Cone Lights doc](https://github.com/phaserjs/phaser/blob/master/docs/Phaser%204%20Cone%20Lights/Phaser%204%20Cone%20Lights.md); [CHANGELOG-v4.2.0](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.2/CHANGELOG-v4.2.0.md)
- Pixel art: `render: { pixelArt: true }` (rounded pixels, avoid scaling, rotating, zooming objects) or `render: { smoothPixelArt: true }` (new in v4, for scaled-up pixels). `pixelArt` also turns antialiasing off and `roundPixels` on. Filters for pixel art: Blocky, Pixelate, Quantize, GradientMap. `roundPixels` now defaults to false (it was true in v3). The config reader also accepts `pixelArt` at the top level of the config. Source: [Phaser 4 Pixel Art Guide](https://github.com/phaserjs/phaser/blob/master/docs/Phaser%204%20Pixel%20Art%20Guide/Phaser%204%20Pixel%20Art%20Guide.md); [Phaser repo `src/core/Config.js`, lines 380 to 415](https://github.com/phaserjs/phaser) (clone)
- The same pixel art guide says general image models usually fail at real pixel art, and that "you'll either have to find very specialized tools, or do a lot of retouching." Source: [Phaser 4 Pixel Art Guide](https://github.com/phaserjs/phaser/blob/master/docs/Phaser%204%20Pixel%20Art%20Guide/Phaser%204%20Pixel%20Art%20Guide.md)
- Removed or changed APIs that matter for code Claude writes from v3 habits: `Geom.Point` removed (use `Math.Vector2`); `Math.TAU` now equals PI x 2 and `Math.PI2` is removed; `Struct.Set` and `Struct.Map` are native `Set` and `Map`; `setTintFill` removed (use `setTint().setTintMode(Phaser.TintModes.FILL)`); `DynamicTexture` and `RenderTexture` need an explicit `render()`; `Mesh` and `Plane` removed (a new `Mesh2D` came in 4.2.0); `Camera3D` and `Layer3D` removed; `Create.GenerateTexture` and `TextureManager.generate` removed; `phaser-ie9.js` removed; compressed textures must be re-compressed with Y flipped; bundled Spine plugins are no longer updated. Source: [Migration Guide sections 4 to 21](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/MIGRATION-GUIDE.md); [official migration article, 16 April 2026](https://phaser.io/news/2026/04/migrating-from-phaser-3-to-phaser-4-what-you-need-to-know)
- `Graphics#generateTexture(key, width, height)` still exists in Phaser 4, so code-drawn textures remain possible. Source: [Phaser repo `src/gameobjects/graphics/Graphics.js` line 1532](https://github.com/phaserjs/phaser) (clone)
- Open issues on the Phaser repo: 108. Recent open items that matter to us: #7351 ("[4.1.0] Camera zoom != 1 with HiDPI canvas: rendering goes blank"); #7341 ("v4.2.1 WebGL sprite batch corruption with an angle tween on a GameObject whose position is also written every frame"); #7331 and #7317 (TilemapGPULayer animated-tile and seam bugs); #7352 (camera follow lerp is frame-rate dependent). No open items in the list concerned lighting, filters, Arcade physics, or audio. Source: [phaserjs/phaser issues](https://github.com/phaserjs/phaser/issues)
- Real use: HADAL (free browser game, 19 Oct 2026) is built on Phaser 4 with a lamp cone, generated normal maps, and Web Audio synthesis with no sound files, and it is hosted on Vercel. Its author's gotchas: "Normals do not flip with setFlipX, so each sprite also gets a mirrored texture", and `setForceComposite` made additive light darken the scene until the glow was drawn into a DynamicTexture with ADD blend. Source: [phaser.io news, HADAL](https://phaser.io/news/2026/10/hadal-phaser-4-deep-sea-game)
- Real use: the-11th-forest (about 25,000 lines, Phaser 4.0.0) and ai-first-starter (Phaser 4.2.1 pinned) are Phaser 4 codebases; wild-adventure's migration notes say moving a top-down Arcade game to Phaser 4 went smoothly: "No deprecations hit us" (self-reported). Source: [the-11th-forest](https://github.com/FireTable/the-11th-forest); [ai-first-starter](https://github.com/boringstack-xyz/Phaser-TypeScript-AI-First-Starter); [wild-adventure](https://github.com/xnt/wild-adventure)
- License of the engine you install: MIT (LICENSE.md, "Copyright (c) 2026 Richard Davey, Phaser Studio Inc."; source headers also say MIT; npm says MIT). A separate product, "Phaser AE", is under PolyForm Shield 1.0.0 (licensor Phaser Studio Inc.; it bars using it to provide a product that competes with Phaser AE). phaser.io page footers link that as "Engine license" under a "Phaser AE" heading, and two automated page summaries misread it as Phaser's own license. The license page itself says "Phaser is open source too." Source: [Phaser LICENSE.md](https://github.com/phaserjs/phaser/blob/master/LICENSE.md); [npm registry](https://registry.npmjs.org/phaser/latest); [PolyForm Shield page](https://phaser.io/polyform-shield-license)

### Inferences
- Phaser 4.2.1 is the right base: it is the only line receiving releases, has the three features this game leans on (cone lights for flashlight and sensor cones, Filters for glasses and near-blind effects, pixel art modes), and ships its own AI-agent skills and TypeScript types that counter Claude's Phaser 3 habits.
- The main risks are: (1) Claude's training skews to v3 APIs, so type-check with `tsc` and point Claude at `node_modules/phaser/skills`; (2) avoid `TilemapGPULayer` (two open bugs) and use plain `TilemapLayer`; (3) avoid camera zoom on HiDPI screens (issue #7351), and scale the canvas with `Scale.FIT` instead; (4) lighting and filters need WebGL and break batching, so keep lights few; (5) pin the exact version and commit the lockfile in case 4.3 changes behavior.
- Phaser 3.90.0 is a valid fallback (it is frozen, so it will not change under us), but it has no cone lights and no Filters, and grid-engine 2.52 and later no longer supports it.
- Michael's September plan said Phaser 3. The evidence says that plan is out of date. This is an engine decision he may want to approve.

- No official statement on Phaser 3's maintenance policy or end of life was found. The evidence is release and branch history only. (The WebSearch budget ended before this could be searched more.)
- The phaser.io announcement post for 4.0.0 was not located. The dates above come from the changelog, GitHub releases and phaser.io/download/stable.
- Nothing was run, so bug reports (#7351, #7341) are judged from titles only.
- The purpose of the unmerged branches `audio-revamp` and `arcade-physics-2` is unknown. I make no claim about future audio or physics changes.

### Inferences
- grid-engine: `~4.0.0` allows only 4.0.x. With Phaser 4.2.1 pinned, `npm install` would likely report a peer-dependency conflict (not run, because installs from untrusted packages were off limits). Options: pin Phaser 4.0.0 (loses cone lights), add an npm `overrides` entry and test, or skip the plugin. The game needs only simple 4-direction tile stepping, a few patrolling robots, and checkpoints, so writing about 100 lines of our own is lower risk. Use grid-engine as a pattern source (Apache-2.0).

- rexUI and rex plugins: not needed for a mouse-light, text-light game. If wanted later, install `phaser4-rex-plugins` through npm; do not mix with `phaser3-rex-plugins`.

## 4. Official templates and create-phaser-game: JavaScript vs TypeScript

### Takeaway
Use the official Vite TypeScript template (`template-vite-ts`), bump Phaser to 4.2.1, and use the `-nolog` scripts. TypeScript pays off because Claude cannot see the game run, and `tsc --noEmit` against Phaser 4's types catches removed v3 APIs.

### Cited Findings
- The CLI command is `npm create @phaserjs/game@latest`. The package is `@phaserjs/create-game` 1.3.2, MIT, with bin `create-game`. It offers bundlers Vite, Rollup, Parcel, Webpack, ESBuild, Import Map and Bun, framework templates (Vue, React, Angular, Next.js, SolidJS, Svelte, Remix), and JavaScript or TypeScript variants. Demo games: Phaser's Revenge, Coin Clicker, Memory Card Game. The page does not state which Phaser version the templates use. Source: [phaserjs/create-game](https://github.com/phaserjs/create-game); [npm @phaserjs/create-game](https://registry.npmjs.org/@phaserjs/create-game/latest)
- `template-vite-ts` v1.4.0, MIT. Its README says updated for Phaser 4, Vite 6.3.1, TypeScript 5.7.2. But package.json pins `"phaser": "4.0.0"` and its description still says "A Phaser 3 TypeScript template". Last commit 21 April 2026. `template-vite` (JavaScript twin) also pins 4.0.0, last commit 29 April 2026. Source: [template-vite-ts](https://github.com/phaserjs/template-vite-ts); [template-vite](https://github.com/phaserjs/template-vite)
- Template layout: `src/main.ts` boots `src/game/main.ts`, which lists five scenes (Boot, Preloader, MainMenu, Game, GameOver) and a config of 1024 by 768 with `AUTO`. The production Vite config sets `base: './'`, terser minification, and a separate `phaser` chunk. Assets in `public/assets` are fetched at runtime; assets imported in code are bundled. Source: [template-vite-ts](https://github.com/phaserjs/template-vite-ts) (clone: README, `src/game/main.ts`, `vite/config.prod.mjs`)
- Telemetry: the template's `log.js` makes one silent call to `gryzor.co` (owned by Phaser Studio Inc.) sending the template name, dev or prod, and the Phaser version. `npm run dev-nolog` and `npm run build-nolog` skip it. Source: [template-vite-ts README, "About log.js"](https://github.com/phaserjs/template-vite-ts)
- Community AI-oriented starters on Phaser 4: boringstack-xyz AI-First Starter (MIT, Phaser 4.2.1 pinned, TypeScript, Vitest, Playwright smoke test, boundary linting, AGENTS.md and CLAUDE.md) and wild-adventure (MIT, AGENTS.md). ### Inferences

## 5. Tools: Tiled, pixel editors, bitmap fonts, placeholder sound, PixelLab

### Takeaway
Tiled (free, GPL editor) feeds Phaser directly through JSON; Aseprite has a built-in Phaser loader but is source-available only; Pixelorama is the free MIT editor. For sound, jsfxr (Unlicense) and sfxr (MIT) cover placeholders. PixelLab can produce characters, tilesets and map objects through an MCP, billed per call.

### Cited Findings
- Tiled: free and open source, current version 1.12.2 (27 May 2026), exports JSON among many formats. Licensing is per file: editor and plugins GPL; libtiled, tmxviewer, tmxrasterizer and the Java library BSD 2-clause; qtpropertybrowser BSD 3-clause. The COPYING file says nothing about maps you create. Source: [mapeditor.org](https://www.mapeditor.org/); [Tiled COPYING](https://raw.githubusercontent.com/mapeditor/tiled/master/COPYING); [Tiled repo](https://github.com/mapeditor/tiled)
- Phaser 4 Tiled import: `load.tilemapTiledJSON(key, urlOrObject)` (the file may be a "well formed JSON object" instead of a URL), then `map.addTilesetImage(nameInTiled, textureKey)` and `map.createLayer(layerName, tileset)`. The parser reads CSV and uncompressed Base64 layers; a compressed layer is skipped with a console warning. "Collection of Images" tilesets are not supported; each tileset must be a single image. External tilesets (a `source` reference to a .tsx file) are not supported either; the parser warns "Use Embed Tileset and re-export". Source: [Phaser tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md); Phaser repo `src/tilemaps/parsers/tiled/ParseTileLayers.js` and `ParseTilesets.js` (clone); `TilemapJSONFile.js` docs (clone)
- Aseprite: source and official binaries are under the Aseprite EULA (not open source). EULA section 2(g) allows compiling or modifying "for your own personal purpose" or to propose a contribution; section 2(b) bars distributing copies to third parties; the EULA does not address ownership of art you make. Some bundled modules are MIT. Source: [Aseprite repo](https://github.com/aseprite/aseprite); [Aseprite EULA](https://raw.githubusercontent.com/aseprite/aseprite/main/EULA.txt)
- Phaser has a built-in Aseprite loader (`load.aseprite(key, texture, atlasJSON)`, then `anims.createFromAseprite`), using the exported sprite sheet and its JSON tag data. Source: [Phaser repo `AsepriteFile.js`](https://github.com/phaserjs/phaser) (clone)
- LibreSprite: GPL-2.0, forked from Aseprite's last GPLv2 commit and developed independently; 70 open issues, 23 open PRs; no last-commit date or release visible in the fetch. Source: [LibreSprite](https://github.com/LibreSprite/LibreSprite)
- Pixelorama: MIT, desktop builds (Windows, Linux, Mac) plus a browser version; exports spritesheets, GIFs and video. Tags are mentioned as a feature but JSON export was not stated. Source: [Pixelorama](https://github.com/Orama-Interactive/Pixelorama)
- Bitmap fonts: Phaser loads BMFont-style fonts (a `BitmapFontFile` loader exists). BMFont (AngelCode) is Windows-only, "freeware and open source" with source under the zlib license, v1.14b beta dated 2025/08/16, outputs text, XML or binary descriptors with TGA, PNG or DDS pages. fontbm is a cross-platform command line BMFont-compatible generator, MIT, with `--data-format` of txt, xml, bin or json and a `--monochrome` option that turns off anti-aliasing. msdf-bmfont-xml (MIT) only makes distance-field output. Source: [BMFont](https://www.angelcode.com/products/bmfont/); [fontbm](https://github.com/vladimirgamalyan/fontbm); [msdf-bmfont-xml](https://github.com/soimy/msdf-bmfont-xml); Phaser repo `src/loader/filetypes/BitmapFontFile.js` (clone)
- Placeholder sound: sfxr's author says it is under "the MIT free software license" and suggests it for placeholder sounds. jsfxr (browser port by Eric Fredricksen, maintained by Chris McCormick) is under the Unlicense, installs with `npm i jsfxr`, and `sfxr.toWave(sound)` returns a WAV data URI. Source: [sfxr (DrPetter)](https://www.drpetter.se/project_sfxr.html); [jsfxr](https://github.com/chr15m/jsfxr)
- Phaser can decode base64 or data-URI audio directly: `sound.decodeAudio(key, data)` accepts "a base64 encoded string, an audio media-type data uri, or an ArrayBuffer". Browsers lock audio until a user gesture: `BaseSoundManager.locked` is true while locked. Source: [Phaser repo](https://github.com/phaserjs/phaser), files `src/sound/webaudio/WebAudioSoundManager.js` and `src/sound/BaseSoundManager.js` (clone)
- PixelLab MCP (https://api.pixellab.ai/mcp, HTTP transport, Bearer token): tools `create_character` (4 or 8 directions), `animate_character` (walk, run, idle and similar), `create_topdown_tileset` (Wang), `create_sidescroller_tileset`, `create_isometric_tile`, `create_map_object` (transparent background, "Auto-deleted after 8 hours"), and raw image tools (`create_image_pixflux`, `create_image_pixen`, `create_image_pro`, `edit_image`, `inpaint_image`, `animate_image`). Jobs are asynchronous: each returns a job id and you poll `get_image`. Output file format and size limits are not stated on the MCP page. Add command: `claude mcp add pixellab https://api.pixellab.ai/mcp -t http -H "Authorization: Bearer ..."`. Source: [PixelLab MCP page](https://www.pixellab.ai/mcp); [pixellab-code/pixellab-mcp](https://github.com/pixellab-code/pixellab-mcp)
- PixelLab API v2 limits and prices (estimates that vary with GPU time): Pixflux up to 400x400, Pixen up to 512x512, Bitforge up to 200x200; skeleton and text animation v3 up to 256x256; 8 rotations v3 256x256. Per call: Pixflux $0.00793 to $0.0132, Character v3 $0.041 to $0.045, skeleton animation v3 $0.0436 to $0.0622, Pro tools $0.08 to $0.15. VFX returns a GIF, a spritesheet with JSON anchor data, or a game-pack ZIP. 4-direction characters are south, west, east, north. Source: [PixelLab API page](https://www.pixellab.ai/pixellab-api); [PixelLab docs, animate with skeleton](https://www.pixellab.ai/docs/tools/animate-with-skeleton)
- PixelLab docs list four ways to use it: web creator, in-browser editor ("PixelLab Pixelorama"), Aseprite extension, and API. The homepage offers a free trial with no credit card. The MCP wrapper repo's license line is "Copyright (c) 2025 PixelLab. All rights reserved." Source: [PixelLab docs](https://www.pixellab.ai/docs); [PixelLab home](https://www.pixellab.ai/); [pixellab-mcp](https://github.com/pixellab-code/pixellab-mcp)

### Inferences

## 6. Project structure for the 9-step level order

### Takeaway
Use one generic scene class per view (side-scroll, top-down, satellite puzzle) driven by data, a single ordered `steps` array for the 9 levels, the Phaser `registry` for shared state, one input module that emits an "intent" object, and a versioned localStorage save with an in-memory fallback. Keep puzzle rules in pure modules that tests can check without a browser.

### Cited Findings
- Phaser scene API: `init(data)` receives what `scene.start(key, data)` passed; `scene.restart(data)`, `scene.launch(key, data)` (a parallel scene such as a HUD), `scene.sleep()`, and `scene.transition()` exist; `this.registry` is a `DataManager` shared by all scenes, and `registry.events.on('changedata-<key>', ...)` fires on change. Source: [Phaser scenes skill](https://github.com/phaserjs/phaser/blob/master/skills/scenes/SKILL.md); [data-manager skill](https://github.com/phaserjs/phaser/blob/master/skills/data-manager/SKILL.md)
- Arcade gravity is a world setting (`this.physics.world.gravity.y`) plus an optional per-body gravity added on top. Source: [Phaser physics-arcade skill](https://github.com/phaserjs/phaser/blob/master/skills/physics-arcade/SKILL.md)
- Scaling: `scale: { mode: Phaser.Scale.FIT, autoCenter: Phaser.Scale.CENTER_BOTH }` is the common setup. Source: [Phaser scale skill](https://github.com/phaserjs/phaser/blob/master/skills/scale-and-responsive/SKILL.md)
- The official template flows Boot, Preloader, MainMenu, Game, GameOver, each a small file (22 to 46 lines). Source: [template-vite-ts](https://github.com/phaserjs/template-vite-ts) (clone)
- wild-adventure (Phaser 4, MIT): `main.ts` sets `pixelArt: true`, Arcade with zero gravity, `Scale.FIT`, and two scenes (StartScene, GameScene). GameScene `create()` builds separate systems (player controller, combat, enemies, UI, collectibles) that talk through an event bus; `update()` reads one intent object from a composite input source (keyboard plus touch). Game over calls `scene.restart()`. AGENTS.md says "No global state; scene resets in `init()`." Fallback textures are drawn in code if PNGs are missing. Source: [wild-adventure](https://github.com/xnt/wild-adventure) (clone: `AGENTS.md`, `src/main.ts`, `src/types.ts`, `src/scenes/GameScene.ts`)
- the-11th-forest (Phaser 4, MIT): "One scene class covers every level"; the level list is an ordered `index.yaml` manifest and each level is data; there is a pure parser and a thin fetch loader. Saves go through one store to one localStorage key with a version suffix (`_v2`), an allow-list of saved fields, about one write per second, and no migration (a new key resets old saves). Its scene cleanup listens for both `shutdown` and `destroy`, with a comment that removing a scene fires `destroy` but not `shutdown`. Source: [the-11th-forest](https://github.com/FireTable/the-11th-forest) (clone: `docs/SCENES.md`, `docs/PERSIST.md`, `src/lib/levels/loader.ts`, `src/game/scenes/scene.ts`)
- ai-first-starter (Phaser 4.2.1, MIT): layers are `domain` (pure functions, no Phaser, no randomness or clock), `runtime` (scenes, entities, input and audio ports), `features` (movement, interaction, save-game, HUD), `content` (level JSON validated by zod schemas), `shared`. The save feature writes a versioned JSON payload through a port that wraps `localStorage`, and loading returns 'missing' or 'corrupt' explicitly. Its `check` script chains typecheck, lint, format, unused-code check, architecture check and tests. Source: [ai-first-starter](https://github.com/boringstack-xyz/Phaser-TypeScript-AI-First-Starter) (clone: `BUILD_THE_GAME.md`, `package.json`, `src/features/save-game`, `src/content/schemas`)
- `Graphics#generateTexture`, `textures.addCanvas`, `textures.createCanvas` and `textures.addBase64` exist in Phaser 4 for code-made or inlined textures. Source: [Phaser repo](https://github.com/phaserjs/phaser), files `Graphics.js`, `TextureManager.js` (clone)

### Inferences
Proposed layout (technique only; story content stays Michael's):
- `steps.ts`: an ordered array of the 9 steps, each `{ id, kind, levelOrPuzzleId, view, glasses }`. Kinds: `earthSide`, `earthTopDown`, `satellite`, `moon`. On a win, the runner calls `scene.start(nextKind, { stepIndex })`. The last step is just a data entry whose content (ending) Michael decides.
- Scenes: `Boot` (build textures, fonts, audio), `Menu`, `EarthSide`, `EarthTopDown`, `Satellite` (one class with a puzzle plug-in per type: routing, sorting, network), and a parallel `Hud` scene started with `scene.launch`. No per-level classes; levels are Tiled JSON or plain data.
- Shared state in `this.registry`, wrapped by a typed `state.ts`: step index, `glasses` (none, on, broken), checkpoint id, hardcore flag, collected items. The HUD listens for `changedata-` events. "Caught, explode, restart at checkpoint" is `scene.restart({ checkpoint })`; hardcore simply changes which checkpoint is used.
- Input: one `controls.ts` returning an intent each frame (move vector, action, throw pebble). Keyboard first; a touch source can be added later without touching game code (the pattern wild-adventure uses).
- Save: a versioned JSON blob under one key, written at checkpoints, read inside try/catch, with an in-memory fallback because storage can throw in private or sandboxed pages.
- Vision and sensors: a `sensors` system owns laser segments and camera cones as data. The glasses toggle an overlay that draws them. For darkness and near-blindness Phaser 4 gives three options to choose between: lights with a low ambient color plus a cone light; a `Mask` filter on the camera; a Vignette filter. Lighting needs WebGL and breaks batching.
- Physics: Arcade for both views. Top-down uses zero gravity; side-scroll scenes set `physics.world.gravity.y`. Display: `pixelArt: true`, a low internal resolution, `Scale.FIT` with `autoCenter`.
- Asset pipeline: Tiled to JSON (CSV layers, embedded tilesets), sprite sheets as PNG plus Aseprite JSON or code-made textures, bitmap fonts through fontbm, audio synthesized in code or from jsfxr. Imported assets get inlined for the single-file build.
- Testing: each puzzle type (zip path validity, packet sorting, bandwidth limits) lives in a pure module with Vitest tests, so Claude can verify rules without watching the screen.

### Gaps
- This layout is a recommendation from patterns in three codebases; nothing was built or run.
- Mobile or touch support is not specified by the brief; a touch input source is optional.

## 7. Shipping: one self-contained HTML file vs a hosted build

### Takeaway
Ship a hosted Vite build for the link the professor opens (Vercel Hobby or Cloudflare Pages, both free), and produce a single-file HTML as an offline backup. Phaser's loader accepts data URIs, and `vite-plugin-singlefile` inlines imported assets, so both builds come from one source.

### Cited Findings
- vite-plugin-singlefile (MIT, v2.3.4, last commit 17 Oct 2026) inlines JavaScript and CSS into `dist/index.html`. Its recommended config (default on) sets `assetsInlineLimit` so every imported asset is inlined, turns off CSS code splitting, and forces dynamic imports inline. README limits: one HTML entry only, dynamic imports may fail under `file://`, no History API routing or cookies, no Worklets or WebXR, no sourcemaps, and a strict CSP meta tag can block inlining. Source: [vite-plugin-singlefile](https://github.com/richardtallent/vite-plugin-singlefile) (clone: `src/index.ts`, `package.json`)
- Phaser loader and data URIs: a `File` has a `base64` flag (added in 3.80.0) set when the URL starts with `data:`, and `ImageFile` switches to the image-element path for base64. `textures.addBase64` exists. Tiled JSON and Aseprite atlas JSON can be passed as objects instead of URLs. `sound.decodeAudio` takes base64, data URI or ArrayBuffer. Source: [Phaser repo](https://github.com/phaserjs/phaser), files `src/loader/File.js`, `ImageFile.js`, `TilemapJSONFile.js`, `AsepriteFile.js`, `WebAudioSoundManager.js` (clone)
- Template README: an asset imported in code is bundled; files in `public/assets` are copied and fetched at runtime; to deploy, "upload *all* of the contents of the `dist` folder to a public facing web server." Source: [template-vite-ts README](https://github.com/phaserjs/template-vite-ts)
- Cloudflare Pages Free: 500 builds per month, 20,000 files per site, 25 MiB per file, 100 custom domains per project. Cloudflare's migration page says "what works in Pages works in Workers" and shows no Pages deprecation notice. Source: [Pages limits](https://developers.cloudflare.com/pages/platform/limits/); [Pages to Workers page](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/)
- Vercel Hobby: free, "non-commercial, personal use only"; includes 100 GB fast data transfer and 100 deployments per day; Password Protection is not available on Hobby (Pro is $20 per month per protected project). The recommended "Standard Protection" setting protects every deployment except production domains, and enabling it makes the production generated deployment URL restricted. Source: [Vercel Hobby plan](https://vercel.com/docs/plans/hobby); [Vercel Deployment Protection](https://vercel.com/docs/deployment-protection)
- itch.io HTML5: upload a ZIP with `index.html` at the root, at most 1,000 files after extraction, 500 MB total, 200 MB per file. A single self-contained HTML file can be uploaded without zipping. Embed can be "Click to launch in fullscreen". Mobile needs the "Mobile Friendly" setting. The page did not cover restricted or password-protected visibility. Source: [itch.io HTML5 docs](https://itch.io/docs/creators/html5)
- HADAL, a Phaser 4 browser game, is hosted on Vercel at game-hadal.vercel.app. Source: [phaser.io news, HADAL](https://phaser.io/news/2026/10/hadal-phaser-4-deep-sea-game)
- Browsers lock audio until a user gesture; Phaser exposes `BaseSoundManager.locked`. Source: [Phaser repo](https://github.com/phaserjs/phaser), file `src/sound/BaseSoundManager.js` (clone)
- From memory (Michael's own statements): michaelendrias.com is hosted on Vercel (he believes it lives only there), and his domains are registered with Cloudflare. This session also lists Vercel and Cloudflare Developer Platform MCP tools, so Claude may be able to deploy directly. Source: user memory (`/areas/personal-website.md`, `/profile.md`); session tool list (no public URL)

### Inferences
- Hosted build: best for a class link (normal caching, smaller assets, easy to update at the same URL). Gotchas: share the production domain, not a per-deployment URL (Vercel restricts those under Standard Protection), and test the link in a private window with no login.
- Single file: one portable file that should work from a drive or offline (not built or tested here; email delivery untested), and fits the claude.ai Artifact route; but base64 adds about one third to asset size, nothing is cached separately, debugging is harder, and every asset must be an import (no `public/` folder, no dynamic imports). Keep assets small; Phaser (1.4 MB) plus a few MB of art is well under the 16 MB Artifact limit and itch.io caps.
- Generating audio in code (jsfxr or Web Audio, as HADAL does) removes the biggest inlining cost.
- Add a "press any key to start" screen so audio unlocks, and wrap storage access in try/catch.
- Per the user's memory, the syllabus lists a first draft on 11/5 and a final on 12/13 (labeled Fall 2025, may be stale), so a playable hosted link should exist well before the final date. Vercel Hobby's non-commercial limit is fine for a class demo.
- itch.io works but adds site chrome and an account; Cloudflare Pages or Vercel is simpler for a one-link demo.

### Gaps
- Not tested: an actual single-file build with inlined audio and Tiled data, or load time on classroom Wi-Fi.
- itch.io draft or password visibility was not verified.
- Cloudflare Workers static-assets limits were not retrieved (only Pages limits).
